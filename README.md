# AI 对话知识库

本目录是一个由 AI 对话沉淀而成的个人知识库。聊天流是按时间线性组织的瀑布流，无法检索；本知识库按**专题**组织，将值得保留的对话结论固化为可检索、可增长的 markdown 笔记。

**任何 AI 助手在本目录下执行"总结存档"任务时，必须遵守本 README 的全部规范。**

---

## 一、工作流程

1. 用户与 AI 就某个专题进行若干轮对话；
2. 用户认为时机成熟（讨论得出结论、或阶段性完成）时，命令 AI 总结刚才的对话；
3. AI 按第四节的固定格式生成一条条目，写入对应专题的 md 文件。

触发时机由用户判断——什么值得记、什么只是过程噪音，AI 不自行判断、不主动存档。

## 二、目录组织
- 根目录为D:\NOTE!!!!!!\AI-generting
- 一级为**领域目录**，二级为**子专题文件**，例如：

```
java/
  collections.md
  concurrency.md
data-structure/
  tree.md
  graph.md
```

- **领域 README 清单**：部分领域目录带有自己的 README.md，记录域内特化约定（与根规范冲突时以根规范为骨架）。目前有：`japanese/`（日语学习域）。新建领域 README 时同步更新本清单。
- 专题文件过大的迹象：超过约 500 行，或一个文件里明显混入了多个子话题。此时应拆分为子专题文件。
- **禁止**把所有内容堆进单个大文件——那等于把瀑布流问题从聊天窗口搬进文件。

## 三、写入规则（重要）

1. **先读后写**：写入前必须先读取目标文件，检查是否已有相关条目；
   - 已有相关条目 → **合并或更新**该条目（修正过时结论、补充新细节），不新增重复条目；
   - 没有相关条目 → 在文件末尾**追加**新条目；
2. **同步目录**：每个文件顶部维护一个锚点目录（链接列表），新增或合并条目时同步更新；
3. **定期重构**：用户要求时，对笔记做整理——合并重复、消除矛盾、调整归类，如同重构代码。

## 四、条目格式（固定）

```markdown
## <结论式或问题式的具体标题>
- <记录日期，格式 YYYY-MM-DD>

**结论**：<一两句话，最常回看的内容，放最前>

**背景**：<为什么聊到这个，可省略>

**细节**：<机制、推导、代码示例——深度内容放这里>

**坑**：<容易犯的错、和直觉相反的点，没有可省略>
```

格式说明：

- **标题**是检索的钥匙。必须是具体、可搜索的标题，如「HashMap 的扩容为什么要求容量是 2 的幂」；禁止「Java 讨论之三」这类无信息量标题；
- **倒金字塔分层**：结论先行，深度内容（推导、代码）后置，兼顾可读性与深度；
- **代码片段原样保留**，不做压缩改写——它们往往是最需要被检索回看的内容；
- 总结是**有损压缩**，但压掉的应该是寒暄、试错过程和跑题内容；结论、坑、代码不允许被稀释。

## 五、质量要求

| 要求 | 说明 |
|------|------|
| 具体优先 | 标题和结论落到具体机制，不写泛泛的套话 |
| 深度可追溯 | 深层细节保留在「细节」区，不因摘要而丢失 |
| 去重去矛盾 | 同一话题多次讨论只留一个条目，以最新结论为准 |
| 时间可查 | 每条目必须带记录日期 |

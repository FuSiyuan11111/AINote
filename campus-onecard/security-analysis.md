## 校园卡系统难攻击的真正原因：卡是最长的板，攻击者不需要碰卡
- 2026-09-21

**结论**：国密 CPU 卡只挡得住「复制卡蹭饭/改卡内余额」一类攻击（M1 时代真实发生过、行业因此强制换 CPU 卡）；代打卡走 UID/酷学途账号路径，**与卡加密无关**；盗账户资金走后台与密码（初始=身份证后六位）；三期升级后资金主要在后台电子支付账户，实体卡丢的只是介质。**安全设计的至高境界不是每个部件攻不破，而是攻破任何单部件都无利可图。**

**细节**：

按攻击目标拆解（每行防线不同，卡只挡第一行）：

| 攻击企图 | 需要破卡的加密吗 | 真正的防线 |
|---|---|---|
| 复制卡消费、改卡内余额 | 需要，且被挡死 | 一卡一密 + SAM + 后台对账 |
| 代打卡、伪造在场 | 不需要 | UID 明文路径 + 动态令牌 + 账号风控（业务层） |
| 盗刷账户资金 | 不需要 | 后台账号密码、App/网页服务 |
| 窥探卡上个人信息 | 视权限设计 | 身份区读取控制 |

CPU 卡防护的边界（诚实清单）：中继攻击对一切 proximity 卡理论可行；后台被攻破/内部人员作案无解；UID 明文是 ISO 14443 协议固有属性，只能靠业务层交叉验证补偿。

**坑**：把「卡难破解」当成「系统难攻击」的原因是因果倒置——卡是最难啃的部件，所以没人啃它，残余风险全部转移到了卡之外（密码、账号、业务流程）。

## 经由卡片攻击刷卡机是死路：卡是被动的定长应答者
- 2026-09-21

**结论**：刷卡机与卡的「信息交流」本质是**机器盘问、卡被动应答的定长协议帧**（防碰撞→UID→认证），没有任何字段会被机器当指令执行——卡上不存在通往机器的代码执行通道。破解卡的密钥，权限上限是「把这张卡合法用明白」；机器侧把射频输入一律按不可信输入处理（读到的只是编号，判定逻辑在服务器），射频口注入异常最多让单笔读卡失败，机器重启即恢复且异常进后台日志。机器的真正漏洞面在固件实现缺陷和后端，对在用设备做这类测试 = 未授权干扰，《刑法》285/286 范畴。

**细节**：

正当的练手途径（替代对着学校设备琢磨）：自购空白 M1/CPU 卡 + 读卡器自建实验环境、打 smart card 类 CTF、读 Nohl 等人破解 Crypto-1 的公开论文；真发现漏洞走负责任披露报告信网中心（0731-88836367），高校信息化部门欢迎此类报告。

**坑**：性质转折点要认清——讨论「系统如何工作、为什么安全」是正当知识；索取「对在用设备的具体攻击方法/工具/步骤」已越界，前者可以聊透，后者拒绝。

## 自购同款打卡机对学校系统无效：终端的权力来自后台注册
- 2026-09-21

**结论**：考勤终端是公开销售的 B2B 商品（威尔官网有商务入口、京东有售；普通考勤机几百至几千元，智慧班牌类上万），**个人购买合法**。但出厂机器 = 空白终端，能干活的前提是三凭证：①设备身份注册进后台白名单（服务器才认它的上报）；②动态令牌由服务端签发给**在册**设备（自购机变不出有效考勤码）；③配置好的密钥/数据通道。自购机器三样全无——码无效、上报被拒、读卡也没有白名单库可比。伪造设备身份骗注册 = 对校园信息系统未授权接入。**买终端买不到它在信任体系里的「编制」；信任从不在终端上。**

**细节**：正当且有价值的用法：自购一台 + 厂商 SDK/文档，自建卡+自建后台，完整复现「刷卡→比对→记录」链路学 RFID 应用开发；低配替代 = 几十元 USB 读卡器 + 开源考勤项目。

**坑**：直觉以为「有了同款硬件就能复刻学校场景」——终端只是信任链的末端传感器，全部权力来自后台注册，这一条对考勤机、门禁、POS 一体机全部成立。

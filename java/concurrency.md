## 进程/线程是对机器本身的抽象，而非业务世界
- 2026-09-21

**结论**：进程/线程和类、接口同属"抽象"，但对象不同——类/接口抽象**问题域**的概念（订单、用户），进程/线程抽象**计算机自己**。进程 = 对"一个正在运行的程序及其资源"的打包抽象（虚拟地址空间 + 文件等资源 + 执行流，感觉独占一台计算机）；线程 = 对"一条独立 CPU 执行流"的抽象（栈 + 程序计数器 + 寄存器副本，感觉独占一颗 CPU）。

**细节**：

类比关系：**程序之于进程 = 类之于对象**——程序躺在磁盘上是静态文件（图纸），运行起来才成为进程（实例）；线程是进程内的一条执行流。进程/线程在抽象层级上对应"对象"而非"类"（运行时实体，会被创建、调度、死亡）。

双重抽象：OS 层面线程是内核的管理机制；Java 的 `Thread` 类又对 OS 线程做了一次面向对象的抽象（把申请/等待/中断包装成 start/join/interrupt）。同一个东西被抽象了两层。

CS 的第一性原理就是抽象：文件抽象磁盘、虚拟内存抽象物理内存、进程抽象"计算机"、线程抽象"CPU"、类抽象问题域概念——每层把下层复杂机制封装成简单心智模型。进程/线程和类只是这栋抽象大厦里不同楼层的住户。
